# تاریخ و پیمایش روزانهٔ گفتگو

در گفتگوی دونفره و گروهی، تاریخ یک‌بار در آغاز هر روزِ بارگذاری‌شده با جداکننده نمایش داده می‌شود و کنار هر پیام فقط ساعت قرار می‌گیرد. نتیجهٔ جست‌وجو تاریخ و ساعت را در دو خط نشان می‌دهد. گروه‌بندی و ساعت تابع منطقهٔ زمانی مرورگر است.

تاریخِ اولین پیام قابل‌مشاهده در نشان شناور و نیمه‌شفاف بالای پیام‌ها دیده می‌شود؛ نوار تمام‌عرض ندارد و فضای پیام‌ها را کم نمی‌کند. نشان هنگام اسکرول ظاهر می‌شود و ۱٫۴ ثانیه پس از توقف، با transition ملایم ۳۰۰ میلی‌ثانیه‌ای محو می‌شود. اصلاح موقعیت توسط چیدمان اولیه آن را فعال نمی‌کند. تا وقتی تقویم باز است نشان باقی می‌ماند و در حالت پنهان کلیک یا فوکوس نمی‌گیرد. تنظیم کاهش حرکت مرورگر نیز رعایت می‌شود. تغییر روز فقط هنگام عبور از مرز روز state را تغییر می‌دهد. کلیک آن تقویم ماهانه را باز می‌کند. ماه/سال با ورودی ماه و دکمه‌های قبل/بعد قابل انتخاب‌اند؛ روزهای بدون پیام غیرفعال‌اند. خطای شبکه retry دارد و خطای بازکردن روز، گفتگو یا تقویم را حذف نمی‌کند.

`GET /api/v1/realtime/polling/:id/days?from=...&to=...&timeZone=Asia/Tehran`

- JWT و عضویت فعلی در همان گفتگو الزامی است.
- from/to زمان ISO هستند؛ بازهٔ نیمه‌باز `[from,to)` و طول آن حداکثر ۳۲ روز است. مرورگر ابتدا و انتهای ماه محلی را جداگانه به UTC تبدیل می‌کند؛ روز یا ماه با طول ثابت میلی‌ثانیه فرض نمی‌شود.
- نام timezone با Intl اعتبارسنجی و به‌صورت پارامتر SQL ارسال می‌شود. timestampهای UTC ذخیره‌شده برای استخراج روز به آن منطقه تبدیل می‌شوند.
- پاسخ envelope معمول و `data.days: [{date: '2026-11-04', messageId: 123}]` است. messageId اولین پیام همان روز با ترتیب createdAt/id است؛ پیام‌های سیستمی هم در تقویم تاریخچه لحاظ می‌شوند.
- فقط روزها و شناسه‌ها دریافت می‌شوند؛ برای انتخاب روز از API window و منطق جست‌وجوی موجود جهت بارگذاری حداکثر ۵۰ پیام اطراف مقصد استفاده می‌شود. پیام مقصد در بالای محدودهٔ دید قرار می‌گیرد. ادامهٔ پیام‌های قدیمی‌تر/جدیدتر و بازگشت به آخر گفتگو حفظ می‌شود.
- کوئری محدود به یک گفتگو و بازهٔ ماهانه است، سقف اجرای SQL ۲٫۵ ثانیه دارد و از ایندکس `(chatId,createdAt,id)` استفاده می‌کند. GET روزها رسید خواندن ثبت نمی‌کند.

migration `20261104150000_message_calendar` ایندکس لازم را اضافه می‌کند. روی محیط مقصد، پیش از راه‌اندازی نسخهٔ جدید بک‌اند `npx prisma migrate deploy` اجرا شود؛ ساخت ایندکس معمولی روی جدول بزرگ نیاز به زمان‌بندی مناسب دارد. migration روی دیتابیس محلی اعمال و تست‌های API واقعی، مرز نیمه‌شب تهران، عضویت و EXPLAIN ایندکس اجرا شده‌اند. تست‌های فرانت گروه‌بندی، ساعت، تقویم، retry، انتخاب روز بارگذاری‌نشده و تغییر تاریخ نوار با اسکرول را پوشش می‌دهند.
