# مرجع فرانت‌اند اصلی — React + Vite

آخرین به‌روزرسانی: ۲۰۲۶-۱۱-۰۳.

## تصمیم قطعی پروژه

**نسخهٔ اصلی و محل تمام توسعه‌های فرانت `frontend/` است.** هر درخواست کاربر دربارهٔ فرانت، صفحه، استایل، UX، روت یا رفتار چت به‌صورت پیش‌فرض روی همین نسخه اعمال شود، مگر اینکه کاربر صریحاً مقصد دیگری مشخص کند.

`nextjs-frontend/` فقط بکاپ موقت است. قرار است بعداً کنار گذاشته شود؛ فعلاً حذف، توسعه یا همگام‌سازی تغییرات در آن انجام نشود. [سند Next.js](nextjs-frontend-context.md) صرفاً بررسی تاریخی بکاپ است؛ ایرادهای آن بدون بررسی کد React نباید به نسخهٔ اصلی نسبت داده شوند. مهاجرت به React انجام شده و دیگر یک گزینهٔ در حال بررسی نیست.

## مراجع و ساختار

- [راهنمای اجرایی و معماری](../frontend/README.md): فرمان‌ها، تنظیمات، استقرار SPA و قراردادهای انتقال.
- [مرجع بک‌اند](backend-context.md): ساختار API، Socket.IO، مدل داده و ایرادهای ثبت‌شدهٔ بک‌اند.
- `frontend/src/app/`: providerها، router و layout برنامه.
- `frontend/src/features/auth/`: API حساب، store نشست، SessionProvider، ProtectedRoute و فرم‌های ورود/ثبت‌نام.
- `frontend/src/features/chat/`: مدل پیام، HTTP API، socket، cache، hookها، سایدبار و صفحهٔ اتاق.
- `frontend/src/features/profile/`: ویرایش پروفایل.
- `frontend/src/pages/`: landing، login، داشبورد خالی و صفحهٔ ناموجود.
- `frontend/src/shared/`: اجزای عمومی، shadcn/ui، hookها، کلاینت HTTP، تنظیم محیط و utilityها.
- `frontend/src/styles/globals.css`: Tailwind و توکن‌های ظاهری؛ `components.json` برای shadcn با `rsc: false` تنظیم شده است.

ساختار feature-based حفظ شود: منطق هر قابلیت در feature خودش بماند و فقط کد واقعاً مشترک به shared منتقل شود. alias `@/` به `frontend/src/` اشاره می‌کند. این نسخه وابستگی اجرایی به Next.js ندارد.

## اجرا و محیط محلی

پورت توسعهٔ فرانت 3003 است. `frontend/.env.local` و نمونهٔ محیط، بک‌اند محلی را هدف می‌گیرند:

```dotenv
VITE_API_URL=http://localhost:3333
VITE_SOCKET_URL=http://localhost:3333/chat
```

کلاینت HTTP prefix `/api/v1/` را اضافه می‌کند. متغیرهای Vite عمومی هستند؛ مقدار حساس در آن‌ها قرار نگیرد. برای فرمان‌های نصب، اجرا، build، lint و تست به README فرانت مراجعه شود. خروجی production در `frontend/dist/` است و سرور وب باید fallback مسیرهای SPA به `index.html` داشته باشد.

## مسیرها و نشست

صفحه‌های `/` و `/login` عمومی هستند. `/dashboard`، `/dashboard/profile` و `/dashboard/websocket/:chatId` زیر ProtectedRoute مشترک‌اند. URL قبلی اتاق چت برای سازگاری حفظ شده است.

نشست در Zustand با کلید `beam-session-v1` نگهداری می‌شود. وجود token به‌تنهایی مجوز نمایش صفحهٔ خصوصی نیست؛ SessionProvider با user-info اعتبار نشست را بررسی می‌کند. خطای موقت شبکه قابل retry است و نشست ردشده پاک می‌شود. HTTP از Bearer و refresh مشترک برای درخواست‌های همزمان استفاده می‌کند. خروج، cache و socket را نیز پاک می‌کند. حفظ این رفتارها هنگام تغییر router یا UI ضروری است؛ مجوز نهایی داده همچنان وظیفهٔ بک‌اند است.

## جریان چت و ادامهٔ اصلاحات

پیام‌ها در TanStack Query نگه داشته می‌شوند؛ store قدیمی پیام Next.js مبنای تغییر نیست. تاریخچه، ساخت چت و جست‌وجوی مخاطب از REST می‌آیند؛ پیام جدید، typing و رسید خواندن از Socket.IO. آرایه‌های تاریخچه/unread در مرز API ادغام و با شناسهٔ پیام حذف تکرار می‌شوند.

صفحهٔ اتاق و فرم ورود lazy هستند. اتاق پس از reconnect دوباره join می‌شود و تاریخچه را تازه می‌کند. ارسال تا ack منتظر می‌ماند، draft در خطا حفظ می‌شود و retry خودکار ارسال وجود ندارد. فهرست چت تا زمان اضافه‌شدن رویداد inbox در بک‌اند، هر ۱۰ ثانیه و پس از رویداد مرتبط تازه می‌شود.

تاریخچه در بسته‌های ۵۰تایی دریافت می‌شود و با رسیدن پیام دهم از ابتدای فهرست به محدودهٔ دید، صفحهٔ قبلی پیش‌دریافت می‌شود. لودینگ مشترک، حفظ موقعیت اسکرول و retry مستقل برای تاریخچهٔ قدیمی فعال‌اند. موارد باقی‌مانده برای بررسی مشترک: تعریف دقیق unread/read، آزمون واقعی چندکاربره و UX موبایل. آپلود عکس پروفایل و عکس/ویدئوی چت به همراه احراز هویت سوکت پیاده شده‌اند؛ [قرارداد رسانه](media-uploads.md) مرجع محدودیت‌ها، API و استقرار است. تماس صوتی و تصویری دونفره نیز مطابق [قرارداد تماس](calls.md) پیاده شده است. یافته‌های تاریخی Next.js باید موردبه‌مورد با این کد تطبیق داده شوند.

در پایان انتقال، build و lint و ۲۰ تست در ۶ فایل موفق بودند؛ خروجی production و fallback لینک مستقیم نیز با HTTP بررسی شدند. این نتیجه مربوط به زمان انتقال است و تأیید دائمی کد یا جایگزین آزمون واقعی مرورگر نیست.

گروه نام‌دار، ساخت دو مرحله‌ای، مدیریت اعضا و مالکیت، خروج و به‌روزرسانی سوکت در ۲۰۲۶-۱۱-۰۴ اضافه شدند. [قرارداد گروه‌ها](group-chats.md) قواعد، API، migration و تست‌ها را ثبت می‌کند. GET تاریخچه دیگر رسید خواندن نمی‌نویسد؛ رسیدها فقط از رویداد message:read برای شناسه‌های مشخص ثبت می‌شوند.

جست‌وجوی متنی داخل هر گفتگوی دونفره/گروهی با پنل نتیجه، API سمت سرور و رفتن مستقیم به بازهٔ پیام قدیمی پیاده شده است. [قرارداد جست‌وجوی پیام](message-search.md) شامل ایندکس‌ها، محدودیت ورودی، migration و رفتار cache در بازهٔ تاریخچه است.

نمایش روزانهٔ پیام‌ها، ساعت مستقل، تاریخ ثابت روز قابل‌مشاهده و تقویم ماهانه با دریافت روزهای دارای پیام از بک‌اند اضافه شده است. [مرجع تاریخ و تقویم](chat-dates.md) رفتار timezone، endpoint، index و تست‌ها را ثبت می‌کند.
